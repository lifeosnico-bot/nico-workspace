Layer 1 — Input Sources

Vincent (CEO)

Ideas, priorities, approvals, decisions

Telegram / Slack / Linear UI / Voice

Letta Bot Briefing

Morning summary, overnight results, blockers

Telegram → Vincent at 8am daily

GitHub Events

Failed CI, new issues, PR comments, Dependabot

Webhooks → Slack #alerts

Client Requests

Lucavo client needs, quotes, change orders

Email / Phone → Vincent → Telegram
all inputs become Linear issues
Layer 2 — Intake & Triage (Nico Owns This)
Step 1: Capture

Linear Inbox

Every request enters as an unassigned issue in the Inbox.
Vincent can create directly. Letta Bot can create via API.
GitHub events auto-create via integration.

Step 2: Triage

Nico Evaluates Each Issue

Sets priority (P1-P4) · Assigns project (Engineering, Ops, Product, Growth) ·
Adds labels (type:feature, type:bug, type:research, type:ops) ·
Determines if issue is agent-sized (5-15 min) or needs decomposition

is this one task or many?

Single Task

Already scoped for one agent.
Move directly to assignment.

e.g., "fix login redirect bug"

Needs Decomposition →

Break into sub-issues. Each sub-issue
is one agent, one branch, one PR.

e.g., "build onboarding flow" → 8 sub-issues

Needs Vincent Input

Business decision required.
Escalate via Telegram/Slack.

e.g., "pricing model for SaaS tier"
triaged issues move to "Todo" in Linear
Layer 3 — Assignment & Routing (Nico Owns This)
Step 3: Route to Agent

Nico Matches Issue → Best Agent

Complex architecture, multi-file refactors  →  Claude Code
Defined implementation, tests, boilerplate  →  Codex
Bug fix with failing test, small patches  →  Copilot
UI components, skill-based work  →  Antigravity
Research, analysis, deep dives  →  Letta Code
Client comms, briefings, memory tasks  →  Letta Bot
Vault docs, SOPs, decisions  →  Nico (self)
Needs human judgment  →  Vincent

Step 4: Dispatch

Issue Assigned in Linear + Worktree Created

Linear issue moves from "Todo" → "In Progress"
Git worktree created: git worktree add ../wt-{agent}-{issue#} -b {agent}/{issue#}-{description}
Agent gets: issue context, branch name, worktree path, acceptance criteria

each agent receives its assignment + isolated worktree

Rule 1 Each agent = 1 branch = 1 worktree
Rule 2 Agent commits often to its branch
Rule 3 Agent NEVER merges to main
Rule 4 Agent opens PR when done
Rule 5 Agent updates Linear: "In Review"
What happens when an agent gets blocked?
Agent adds blocked label on Linear issue → Slack #alerts fires notification → Nico or Vincent unblocks → Agent resumes
agent finishes → opens Pull Request on GitHub
Layer 5 — Review & Merge Pipeline (GitHub Owns This)
PR Opened Agent pushes branch,
opens PR on GitHub
→
CI Runs GitHub Actions:
tests, lint, type-check
→
Auto Review Copilot Code Review
checks for issues
→
Nico Review Architecture check,
consistency, quality
→
MERGE Nico or Vincent
merges to main
At each gate, what can happen:
CI fails → PR stays open → Agent gets notified → Agent fixes on same branch → CI re-runs
Review has comments → Agent addresses comments → Pushes update → Re-review
Merge conflict with main → Agent rebases its branch → Resolves conflicts → Re-runs CI
Merge conflict with another PR → Nico decides merge order → First PR merges → Second rebases
All checks pass → Merge to main → Delete branch → Clean up worktree
merged PR triggers downstream updates
Layer 6 — Post-Merge Automation

CI/CD Deploy

GitHub Actions deploys to staging/prod

main branch → auto-deploy pipeline

Linear → Done

GitHub integration auto-moves issue to "Done"

bi-directional sync via branch name

Worktree Cleanup

Merged branch deleted, worktree removed

git worktree remove ../wt-{agent}-{issue}

Slack Notification

"PR #42 merged: auth module complete"

#status channel + relevant #project
feeds back into the system

Nico Checks for dependent issues → unblocks next tasks
Metrics Cycle time, throughput, agent performance tracked
Parallel Flows (Non-Code Work)
Knowledge & Documentation Flow
Research tasks (Letta Code / Gemini / ChatGPT)  →  findings written to vault 30-resources/  →  linked from Linear issue comment
Decisions (Vincent via Nico)  →  appended to decisions.md (append-only, never edited)  →  referenced in future issues
SOPs & Processes (Nico)  →  written to 20-areas/  →  linked from AGENTS.md for agent context
Session notes (auto-generated)  →  written to 00-dashboard/llm-sessions/  →  session-index.md auto-regenerated
Client docs (Nico + Letta Bot)  →  written to 20-areas/clients/  →  linked from client's Linear project
ONE WRITER PER FILE Only the designated owner edits. Others read only.
VAULT = KNOWLEDGE ONLY Tasks live in Linear. Code lives in GitHub. Vault = docs + decisions.
GIT-BACKED Vault is a git repo. Changes tracked. Conflicts resolved via git.
Communication & Escalation Flow
Routine status: Agent updates Linear issue status → Linear syncs to Slack #status → Letta Bot reads for briefing
Agent blocked: Agent labels issue "blocked" → Slack #alerts fires → Nico evaluates → if needs Vincent: Telegram ping → Vincent responds → Nico unblocks
Overnight result: Overnight runner completes → draft PRs created → Letta Bot adds to morning briefing → Vincent reviews at 8am
CI failure: GitHub Actions fails → Slack #alerts → Nico assigns back to agent → agent fixes → re-runs
Client escalation: Client contacts Vincent → Vincent creates Linear issue tagged "client" P1 → Nico triages immediately
Emergency: Any agent can trigger iMessage alert via imessage-alert.sh → goes to Vincent's phone
Overnight Autonomous Cycle
10pm Nico queues overnight issues in Linear tagged "overnight-ok"
2am Overnight runner reads queue, creates worktrees, dispatches agents
2am–7am Agents work in isolated branches. Max 5 issues. No merging.
7am Draft PRs ready. Summary generated. Letta Bot compiles briefing.
8am Vincent reviews overnight PRs. Merges or requests changes.
Safety rails: max 5 issues · "overnight-ok" label required · no schema migrations · no destructive ops · no auto-merge · alert on any failure
